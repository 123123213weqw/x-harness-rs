# 闲置会话历史缓存验证（2026-09-13）

## 范围

只修改共享 Web Runtime、可重建补丁、静态包、测试、规范与 CI；没有编译 Rust、调用真实模型、删除服务端历史或重启生产应用。当前工作树尚未发布。

规范：[前端闲置会话历史缓存](../specs/session-history-cache.md)。

## 实际实现回归

浏览器加载仓库打包的 Runtime / SessionManager / Session / Chat 注册定义，不是单独重写一个假的 LRU。

- WZU_Server Chromium：27 项生命周期断言，连续三次通过。
- 本机 WebKit：同样 27 项断言通过。
- 覆盖实际 Chat 多页历史投影、事件/views 恢复、当前/运行/待答/审批/排队/在途命令保护、数量与容量上限、真正 LRU、延迟历史请求落地后清理、cold 重连不重新填充、错误保留与重试、消失的恢复范围、旧 open/loadOlder generation、scope drop。
- Chromium 强制 GC 后，清理前 raw events 数组和实际 event 对象的 WeakRef 均失效，证明不只是把计数器改成零。
- 同批远程回归：消息 DOM 窗口化和真实 ChatView 滚动、assistant 思考/正文投影、消息编辑 40 项生命周期断言及 3 项契约、消息编辑浏览器、问答浏览器、子 Agent 返回导航全部通过。
- 本机 WebKit 消息 DOM 窗口化/真实 ChatView 滚动也通过。
- 语法检查与 git diff --check 通过。

首次子 Agent 导航回归因旧测试依赖目录没有 React 18 UMD 文件无法启动。随后在服务器独立测试依赖目录安装 React/ReactDOM 18.3.1，复用现有 Playwright，重跑通过；未修改用户原有依赖目录。

## JS 堆实验

同一浏览器依次对照：32 个合成会话，每会话 160 个事件，每事件独立分配约 2 KiB 文本。对照关闭闲置上限，实验开启默认策略；二者均保留同一个当前会话。每次测量先触发 Chromium GC。

| 次数 | 不限制历史缓存 JS heap（bytes） | 有界历史缓存 JS heap（bytes） |
|---|---:|---:|
| 1 | 20,086,684 | 11,052,208 |
| 2 | 20,092,384 | 11,057,272 |
| 3 | 20,098,560 | 11,064,100 |

中位数 **19.16 MiB → 10.55 MiB，减少约 45%（8.62 MiB）**。

- 对照驻留 31 个闲置历史；实验驻留 6 个，清理 25 个；当前会话均保留。
- 闲置历史的估算数据权重从 22,842,288 降到 4,421,088 bytes。这个权重与上面的 JS heap 是不同指标。
- 不能据此宣称 Mac App/WebKit 总占用下降 45%；系统 WebKit、图片、当前大对话和其他插件缓存不在这个实验的覆盖范围。
