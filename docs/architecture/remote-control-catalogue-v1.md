# Scoped controller catalogue and session selection

These trusted gateway primitives let an authenticated transport discover and select existing granted sessions without exposing the desktop workspace/session RPCs or directory paths. The private Telegram /sessions command now composes durable ingress, native metadata cuts and result/outbox replies. Private Telegram /select now has an inbox-owned atomic route receipt and reply proof. Mobile catalogue transport and channel creation remain unfinished; native and protocol fixtures do not constitute real-channel/model acceptance.

## Catalogue authority and metadata

The transport supplies Subscription identity after its own authentication. `Gateway::controller_catalogue` verifies principal Host, active permission, exact channel/account/user, conversation, binding ID and generation through the private journal. Neither IDs nor pagination cursors grant access. It checks the current bound native workspace/session with the existing scope seam, then submits only the current allowed IDs to `ApiBackend::scoped_catalogue`. Each native seam has a two-second deadline; storage uses the existing journal transaction queue. The current-binding preflight can hydrate that authorized session, but candidate discovery never bulk-hydrates or starts title/model work.

BasicHost reads registered workspace/session/header metadata under its ordinary state/header locks. Both allowlists and native workspace ownership must match. Archived, deleted, unknown or foreign-path sessions are omitted. The page carries allowed workspace IDs/display names and session IDs, optional projected titles, running/restoring state, and an optional next cursor. There are no cwd, model configuration, credential, raw RPC or internal event fields. User-written titles remain user-written metadata, not a guarantee that their text contains no path-like strings. A cold header without a projected title returns None and restoring=true rather than inventing a title or claiming a recovered task.

Workspace names are bounded to the existing 256-workspace grant limit. Session scope is bounded to 4096 IDs, and each page has at most 25 sorted unique (workspace, session) pairs. The next cursor is exactly the final pair of a full page when another candidate exists. It must remain within the caller's current allowlists. Both native and gateway validate metadata bounds, ownership, ordering, uniqueness and cursor before returning it. Closed serde DTOs reject additive path/raw fields instead of serializing a global catalogue and filtering only at the frontend.

Each page is a fresh native metadata cut, not a pinned multi-page snapshot or a durable credential. Deletion/archival between pages may change results. New controller actions must revalidate live authority; a previously cached page is never permission to execute. Unsupported ApiBackend implementations fail closed and have no generic RPC fallback.

## Selecting an existing granted session

SessionSelection contains only workspace and session IDs. `controller_select` holds the principal's exclusive policy gate, reads exact current identity/binding, rejects targets outside either allowlist before native lookup, and requests a native cut for that one target. An absent or already archived/deleted target fails without changing the binding. The native cut is the scope check, not an atomic lock over future desktop archival or session movement; subsequent commands retain their own fresh native scope checks.

Selecting the current target returns the existing binding without incrementing generation. A different target advances the binding's generation with checked arithmetic and preserves principal identity/revision, conversation and binding ID. The commit rechecks exact principal/binding and writes only that binding in a FULL transaction. The owned write guard stays inside a queued SQL job through commit/rollback even if the asynchronous caller is cancelled, preserving the policy epoch used by paused subscriptions. Native sessions and tasks are not created, cancelled or replayed by selection.

Old generations fail catalogue and subsequent selection, and existing admission/ticket/outbox/subscription checks fence their old scope. A lost selection receipt is an unknown outcome: reload the authoritative route instead of guessing/retrying generations. Selecting cannot grant new sessions or create capabilities. A separate explicit create permission and deterministic native creation receipt are still required for session creation.

## Verification and product limits

API contracts cover closed DTOs, bounded metadata, malformed ownership, ordering/cursors and a fail-closed unavailable backend. Native tests cover 30-session pagination, projected titles/status, registered ownership, archive/delete filtering and cold-header discovery without activation. Gateway tests cover identity dimensions, unauthorized cursor/response, native filtering, deadline/revoke, close/reopen, exact selection, stale generation, no-op selection and unchanged authority. Test fixtures use no real model or provider account.

All three native PR CI jobs explicitly require native catalogue, gateway catalogue and durable catalogue-command fixtures; executing those jobs and native OS runtime acceptance remains pending. Desktop complete-grant Settings now configures multiple workspace/session targets and default-off creation capabilities atomically. Telegram /sessions lists existing authorized sessions without changing those grants or the current route. It does not create a controller credential or mobile relay route. Telegram /select composes the separate existing-grant mutation without rewriting its original authenticated delivery; see remote-control-selection-commands-v1.md. Mobile selection, channel creation transport, schedules and full real-platform/model acceptance remain part of the active Goal. See remote-control-catalogue-commands-v1.md for durable command and reply composition.
