# 页面与弹层优先级

本规范覆盖自有 TS 前端的设置弹窗、下拉菜单、通用确认弹窗，以及窄屏侧栏。修复不得改动模型调用、Profile 持久化或会话协议。

## 弹层与键盘

- 设置和通用 Modal 使用共用 `DialogSurface`，进入浏览器原生顶层，不靠增加 z-index 模拟模态。背景自动不可交互。
- Tab 和 Shift+Tab 在当前弹窗内循环；关闭后把焦点返回仍存在的打开按钮。
- 下拉菜单的 Portal 必须进入所属原生 dialog，避免被原生模态当成背景禁用。
- Esc 优先关闭最后打开且属于当前模态的菜单，并阻止原生 cancel；无菜单时只关闭顶层弹窗。
- 原生 cancel 同时阻止 React Portal 祖先冒泡，避免内层关闭动作误关外层。
- 嵌套确认框关闭后，外层设置必须保留。不执行确认即不产生业务写入。

## 窄窗口

- 640px 及以下设置页采用顶部横向可滚动导航，表单独占内容宽度，不让固定 188px 导航挤压表单。
- 1024px 以下侧栏默认保留 56px 控制轨；手动展开为覆盖式抽屉，不改变聊天输入框宽度。
- 抽屉遮罩提供关闭按钮，选择会话后收起；宽屏拖拽偏好保持不变。
- 侧栏与右侧工作区的覆盖抽屉必须以整个 Frame 为包含块，不能继承预留的 56px 或 0px 网格轨道；右侧按钮须处于视口内且高于遮罩。停靠模式仍保留明确列位置。
- 收起的设置图标保留本地化可访问名称。

## 验收

`test-page-priority-browser.mjs` 使用实际生产整图与隔离 fixture transport，覆盖菜单 Esc、鼠标选择、正反向 Tab、焦点恢复、嵌套确认、426×664 设置布局、抽屉输入框宽度及收起的设置名称。Chromium 与 WebKit 分别执行，并纳入 CI。

迁移差分继续比较原有卡片几何、颜色和像素；允许的结构变化仅是原生模态运输层。冻结基线不得修改。桌面原生 WebView 和发布安装包仍需单独验收。
