# 桌面更新面板的层级与交互

## 问题

2026-10-02 在本机 XHarness 0.2.31 复现：更新组件是 body 下的 fixed 元素，
但没有显式层级。聊天输入区是 sticky、`z-index: 7`，其背景渐变可画到更新面板上，
也可能拦截面板底部的按钮。原测试只有普通聊天背景和 shell overlay，没有输入区，
因此只验证了「更新不能盖住设置」，没有验证「输入区不能盖住更新」。

## 层级契约

```text
普通内容、聊天输入区、本地工作区抽屉（0～10）
                  < 桌面更新组件（11）
                  < shell overlay（20）、设置／审批等全局弹窗
```

- 更新面板不是最高层，不使用极大的 z-index 或浏览器 top layer。
- 面板是 `role=dialog`、`aria-modal=false`：标明浮层身份，但不锁定聊天。
  面板位于 Shadow DOM 中，不能据此证明原生子 WebView 已正确让位；该遮挡恢复须随安装包单独验收。
- 短窗口中限制面板高度并允许内部滚动，长更新说明和重启确认按钮不能跑出屏幕。
- 面板内部 Escape 只关闭更新面板并把焦点还给下载图标，不传播到其他页面的关闭快捷键。
- 不改变更新状态、下载／验签／安装控制器，不自动重启，不改用户会话或任务。

## 回归

`scripts/test-desktop-updater-layer.mjs` 读取严格源码一致的 shipped AppFrame、
ConversationRoot 样式，运行实际 updater bridge。不是用一个普通背景替代 sticky 输入区。

覆盖 Chromium 和 WebKit，各 24 个层级场景：1254／600／360 px 窗口、56／260 px
侧栏、可下载／已下载／下载中／错误状态。对关闭、主操作、诊断按钮分别做真实命中检查；
再验证全局浮层覆盖图标和面板、点击不穿透、Escape／焦点、长说明／确认滚动、输入草稿可编辑。
测试 mock Tauri，不调用模型，不安装更新。

可用 `UI_TEST_UPDATER_SOURCE` 指向旧脚本做反证。本机旧安装脚本在第一个场景的诊断按钮
命中检查失败；修复后两引擎通过。14 个原更新器状态／命令回归也通过。

改动先进入源码和 3083 的静态构建；本机 `.app` 未替换、未重签、未重启。
CI 中沿用已有的两引擎层级测试入口。源码测试通过不等于新安装包已经发布。

维护入口为 `ui/src/desktop/updater.ts`，层级测试通过 `scriptAsset()` 编译实际 TS 脚本，
UI 构建生成 `ui/dist/desktop-updater.js`。旧 JS／reference 只作迁移固定基线，不另维护第二份运行逻辑。
