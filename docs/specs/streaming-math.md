# 流式公式渲染修复

日期：2026-09-13。实现和静态包已更新，尚未发布或替换运行软件。

## 原因

`MarkdownText` 的两条路径不一致：流式增量 parser 使用未启用数学扩展的解析函数，完成后全量 parser 才启用数学扩展。KaTeX 和字体已存在，故表现为回答结束后公式才排版。

## 修复

- 流式增量 parser 复用最终 Markdown 的数学扩展，不新增数学库。
- 保留原有 frozen/tail 缓存；完整的旧块和其 React 节点继续复用。
- 支持原最终解析器已有的 `$…$`、`$$…$$`、`\(...\)`、`\[…\]`。
- 流式块公式需确认闭合，未闭合则保持原文；避免完整文档解析器在 EOF 容忍未闭合数学围栏、提前交给 KaTeX。
- 正文中已经闭合的公式立刻具备渲染条件，不等待后面的公式或整个模型 turn。
- 不对全量字符串做分隔符替换；代码块、行内代码、转义沿用 Markdown 语义。
- 不改变网络接收、工具调度、后端历史、思考纯文本显示或最终 Markdown 的原有解析行为。

## 接入与测试

`ui/overrides/streaming-math.js` 保存维护源码，`scripts/patch-streaming-math.mjs` 按解析函数和增量 parser 的结构定位打包入口（不绑定压缩变量名），不匹配则报错。

`rebuild-ui.sh` 自动应用；静态入口生成新的内容哈希并更新 index.html，防止客户端继续命中旧缓存。测试从 index.html 读取实际使用的入口，不能任取目录里另一个旧 index 文件。

`scripts/test-streaming-math.mjs` 加载真实打包 MarkdownText，逐字符输入：四类分隔符、矩阵、中文/希腊字母、代码隔离、转义、未闭合公式、前完整后不完整、完成前后等价、冻结节点身份、替换重置和非法 TeX。

本机 WebKit 与 WZU_Server Chromium 的 18 组检查通过；CI 已接入两个引擎。发布仍需远端 CI 门禁，不代表已安装 App 已生效。
