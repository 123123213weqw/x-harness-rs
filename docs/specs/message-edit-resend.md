# 历史消息编辑后重新发送

## 语义与入口

PR #35 的功能不是修改历史，而是将用户消息恢复到输入框，编辑后通过现有
`session.prompt` 创建新一轮。原消息、后续回答、工具记录不变，不自动回滚文件。
会话停止后显示“编辑并重新发送”；运行中不提供入口。图片消息也可编辑。

## 草稿事务

- 输入框已有文字或图片：确认替换后才恢复历史消息；先持久保存原草稿。
- 编辑期间可改文字、添加或移除图片；取消编辑恢复原文字和原图片。
- 同一会话一次只允许一个编辑事务；不同会话按 sessionId 隔离。
- IndexedDB 保存原草稿和编辑草稿；图片引用不保存 base64，未发送的本地文件保存
  ArrayBuffer + 名称/MIME/时间，避开 WebKit File Blob 事务兼容问题。
- 相同不可变 File 的字节读取缓存复用，避免每次键入重复读取图片。
- 刷新后提示恢复，不静默覆盖新草稿。恢复/取消发现新的文字或附件时阻止覆盖。
- 持久化失败显示错误；初次保存失败不替换原草稿。
- 发送失败保留当前草稿；确认发送成功后清理事务。清理期间禁止再开启编辑，避免
  旧事务删除新草稿。发送进行中禁止移除仍被该次请求使用的图片。
- 草稿持久化范围是同一浏览器 origin。清除网站数据会删除草稿；桌面换端口/换 origin
  的跨重启迁移不在此功能保证内。已提交的历史仍由 Host 持久化。

## 附件与协议

复用 `session.readAttachment` 预览与附件归属检查，`session.prompt.content` 扩展：

```json
{"type":"image_ref","attachmentId":"已存在的附件 ID"}
```

Host 根据当前会话的真实历史解析附件所有者；合法分叉继承可使用祖先图片，
无关会话不可引用。客户端不能指定 owner。引用发送不重新上传文件，落盘仍为现有
`image + attachment`，Provider 和历史读取不需要另一套协议。

图片丢失/读取失败显示重试和移除入口，禁止默默改成纯文本发送。迟到的预览响应
不能复活已移除的图片。模型能力明确 `imageInput:false` 时在接收前拒绝；未知能力
不依据模型名称猜测。子 Agent 延续仍沿用现有图片不支持的显式错误。

编辑发送附带 `requireIdle:true`。Host 在已有 admission 锁内检查运行状态，
调度后台启动也使用该锁，防止检查与发送之间开始另一轮。普通消息不改变原来的
排队/Steering 行为。相同 RPC 的已接收重试继续沿用原 receipt 去重。

## 验收

- Node 控制器测试：草稿确认/取消、文本与图片、失败/重试、刷新恢复、会话隔离、
  存储失败、保存中输入、迟到图片响应、重复点击与异步清理竞争。
- Chromium + WebKit：实际发布 bundle、真实 InputMachine/InputBar、确认/取消、
  发送失败保留、重复发送、图片缺失恢复、运行态阻止、窄屏及 IndexedDB 刷新。
- 实际 ConversationController：图片引用未重编码，requireIdle 传递，失败不释放附件。
- Rust Host：原历史不变、新消息复用同一附件 ID、跨会话拒绝、分叉引用、坏引用、
  运行态拒绝、错误参数类型、切换到不支持图片的模型时拒绝。
- 源码补丁签名、幂等与 boot graph/hash 一致性；三平台 CI 回归。
