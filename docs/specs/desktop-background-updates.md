# 桌面后台准备更新（2026-10-03）

## 体验与复用

沿用 Tauri 2.11 更新器、原 HTTPS 清单、公钥、原生平台安装器、Host 有序退出与本机自签可选路径，不造第二套安装器，不修改发布通道或 Apple 公证策略。

- 启动后 1.5 秒和可见页面每 6 小时检查并准备新版；恢复网络可再次准备。
- 检查、下载、验签和缓存均不展开更新面板、不停止任务、不触发安装。
- 下载完成后蓝色入口提示“重启更新”。用户打开面板点重启，仍保留一次停止任务确认；“稍后”仅关闭确认，不安排偷偷重启。
- 关掉软件后完整候选包仍在缓存中；下次取得最新清单且候选身份一致时重新验签，无需重下完整包。
- 自动检查／下载失败以 30 秒、2 分钟、10 分钟三次退避重试；耗尽后保留手动重试。安装失败不自动重试，不被后台检查覆盖。
- 页面退出注销事件和定时器；已发出的检查返回后不得接着发下载。重复点击、定时器和网络事件复用原 controller 与原生更新互斥门禁。

## 缓存信任与存储

应用 Cache 目录下独立 `updater-v1/current/{record.json,package.bin}`，只保留一个正式候选。发布暂存代替反复备份应用／对话；替换时最多额外一个候选大小，成功清理旧代。

身份包括：编译期 feed、公钥、实时清单选出的版本、目标、包 URL、签名。缓存不能自选候选，不能只凭缓存中的哈希认定可信。包恢复及停止 Host 前再次执行与 Tauri 相同的 Minisign 公钥验签，包括 trusted comment 校验；修改、损坏、缺文件、密钥／URL／平台漂移均不得安装。

临时目录写完、文件 sync 后才发布到 current；写失败不发布半包。中断留下的代只影响更新缓存命中，不能阻止 Host 启动。新下载会清理私有暂存代。一个缓存包上限 1 GiB，record 上限 64 KiB；拒绝目录／文件符号链接。这里的包容量限制是缓存门禁，不声称 Tauri 网络下载实现已变成流式落盘。

Ready 状态只保存候选描述和路径，不常驻完整 `Arc<Vec<u8>>`。下载／验签／安装期间仍会短暂使用完整字节：Tauri 的现有 API 要求如此。磁盘 IO 与验签在 blocking worker 中执行，不阻塞 WebView 的 IPC 执行线程。

## 安装与边界

- 读取和验签失败发生在 Host 退出之前：Host 不受影响，Ready 失效，转为可重新下载错误。
- 保留原安装确认、Host 停稳门禁、Windows 当前安装路径、自签校验与回滚逻辑。
- 不承诺新增通用“新版启动失败自动回退”，更不回退用户数据格式；启动健康收据与跨版本恢复应独立验收。
- 新进程需要先获取最新清单；离线时不会仅凭历史缓存直接升级。完整包缓存不是 HTTP Range 断点续传，下载中断仍从头重试。
- 不修改 Gatekeeper、quarantine，不在 CI／安装包内置本机签名私钥；未公证首次安装授权保持原策略。

## 验收

Rust 在远程 V100 隔离源码目录验证 cache/state 与全部 desktop lib 单元测试、check、clippy；Node 验证 controller 和真实 DOM 桥接；Chromium／WebKit 验证后台准备不弹面板、Ready／重启确认、层级、Escape 和任务输入框仍可编辑。

本轮源码结果与边界记录见 [回归记录](../evidence/desktop-background-updates-20261003.md)。Unix 原生验收仅在隔离基础包中暂停统一后台准备入口，避免驱动和自动计时器争抢；生产候选不修改。

源码回归与发布验收区分：跨平台 CI、候选安装、真实发布及本机软件升级未做时不得宣称已上线。复用原 Unix／Windows 实包验收，不修改真实会话与更新 feed。
