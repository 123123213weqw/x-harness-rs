# 工作区项目规则（AGENTS.md）

**Owner：** `xharness-host::instructions`；复用 `xharness-fs` 的受限读取与
`xharness-prompt` 的内容寻址装配。**不增加模型工具、后台 watcher、记忆数据库或问答写入端口。**

## 文件与作用域

- 自动加载源只能是当前 Session 绑定 `cwd` 的 `AGENTS.md`；不是安装目录、Host 启动目录、
  Shell 上次 `cd` 后的目录，也不向上搜索用户 Home 或另一个项目。
- 根文件中的项目规则适用于该工作区。同工作区不同对话可以共享规则，各自的历史和 Goal 仍独立。
- 子目录采用按需读取：提示词要求模型在处理目标文件前，使用已有文件工具检查工作区内沿途的
  `AGENTS.md`；更具体的规则只在对应子树覆盖冲突的父规则。**当前没有子目录自动发现/注入、
  递归扫描或确定性“已读规则才能写入”Guard**，不得将提示词指导宣传成这些能力。
- 项目文件不能授予工具权限、跳过审批或覆盖 Host/用户的更高优先级约束。

## 有意维护，不是自动记忆

用户明确要求持久化项目规则，或者授权的代码改动需要同步修改已有规则时，模型可以复用
read/edit/write 工具进行局部维护，遵守已有观察版本/CAS 和权限路径，并报告实际 diff。
新发现的经验应先建议；不能因一次问题回答、任务结束、错误、临时选择而自动追加。
这是模型行为指导，不是阻止普通文件工具编辑 `AGENTS.md` 的独立 ACL。

`ask_user_question` 的普通/迟到/重放回答均不调用本模块。本模块没有写入 API，不创建文件。
`MEMORY.md` 自动经验、全局偏好和新专用工具均不在此变更范围内。

## 轮次与版本

1. Host 复制 Session 对应的基础 Prompt Sections，释放全局状态锁，再读取规则文件。
2. 文件载入完整 UTF-8 内容，形成 `workspace/instructions/AGENTS.md` Section；内容包含来源和
   工作区作用域。沿用 `PromptSection::content_addressed`，不另建版本表。
3. 实际开始一轮时捕获新快照。持久 Agent 的 `DurableTurnFactory` 重新捕获，因此排队时的
   文件版本不能锁住将来真正执行的轮次；Goal/Schedule 使用同一捕获入口。
4. 同一 Loop 内的工具后续步骤、Provider 网络重试和 Compact 继续使用不可变 PromptAssembly；
   修改文件不替换正在执行的快照。下一轮检查到修改/删除后生效。
5. 规则通过系统提示词的项目规则段提供，不反复追加为用户消息或历史注入；仍占用输入预算。
6. 进程重启后的新 Loop 会重新读取当前文件；本变更不新增“跨进程恢复未完成轮次的旧规则正文”协议。
   历史请求仍由既有 Harness Snapshot 保存当时实际提示词及 Section 哈希，查看历史不能换成当前文件。

Harness 页面复用现有实际请求快照，无需新增页面、UI 状态或第二套内容来源。未经实际请求的
规则不能被显示成已经发送给 Provider。

## 读取边界与失败

- 使用 `FsService` 的目录能力与 `read_preview_bytes`，拒绝符号链接目标、目录、特殊文件及越界；
  不复制一套容易竞争的 `canonicalize → read` 检查，不把预览读取变成模型写入授权。
- 总文件上限 **64 KiB**，按最多上限 + 1 字节读取；超限或非 UTF-8 明确失败，不能静默截断规则。
  UTF-8 BOM 可忽略，空文件/缺失文件正常视为无规则。
- 每 Host 最多 4 个加载任务，包含排队的 5 秒软期限。超时不启动模型请求；底层 OS 读取若仍在运行，
  自持有并发槽直到结束，不能通过超时不断生成无限后台读取。
- 错误走已有 RPC/Agent 错误路径，不能假装成功加载。权限捕获失败时不发布新的 active permission。
- 启动恢复时，坏规则只阻止对应 Session 自动续跑，保留未消费 Inbox 并记录 startup issue；
  不让一个项目文件阻止整个 Host 启动。修复文件后可重试原恢复流程。
- 不缓存正文或假设 mtime 可靠；有界小文件每次读取并计算有效内容哈希。写入并发变化由底层 FsService
  检出；不承诺对不合作的外部写入者提供全文件系统事务。

## 旧托管区

`XHARNESS:USER-MEMORY:BEGIN/END` 内的旧问答内容不再被标为“用户批准的持久目标”，也不提升为
项目规则。自动装配仅排除这些区段，文件保持原样。重复完整区段均排除；不配对/嵌套标记明确报错，
避免将意外暴露的旧答案当作规则。清理旧文件必须另有用户授权。

## 架构与回归

Host 新增唯一向下依赖 `xharness-fs`，并显式更新架构基线：用于复用已存在的受限文件读取，避免
Host 内重新实现 Unix/Windows 文件句柄逻辑；没有反向依赖，PromptAssembler 仍不做文件 I/O。

零付费验收覆盖：缺失/空/BOM/中文、边界字节/超限/非法 UTF-8、旧区段排除及格式错误、符号链接和
同名目录、跨工作区、非递归子目录、修改/删除与稳定哈希、状态锁可用性；真实 Host/Loop + 脚本 Provider
验证普通/持久两条运行时的排队刷新和同轮固定，以及 JSONL 冷恢复后新轮次更新、旧 Harness 快照不变。
这些不是模型自主执行能力或原生 GUI 的评测。
