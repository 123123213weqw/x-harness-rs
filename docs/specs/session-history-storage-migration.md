# 历史存储的无损渐进迁移

## 目标与边界

本机大量历史数据主要来自旧 JSONL 中重复的请求审计，以及新版本 `request-audit/` 的按内容寻址对象。**不允许用删除历史或缩短上下文冒充存储优化**；普通历史、按需请求审计、会话恢复及未来追加必须保持可用。

迁移应分成独立、可验证的阶段，不在一次启动中重写全部文件，也不以升级失败阻止用户打开会话。

## 第一阶段：启动只枚举头部（本次）

- `Store::scan_startup_candidates` 为可选的启动候选接口。普通 Store 默认调用原来的完整扫描；JSONL Store 只读取并校验不可变的首行 Header。
- Host **逐个完整 `load` 后才发布**会话，坏尾部、缺失文件仍进入启动问题报告，其它会话继续恢复。
- 严格的 `list_headers` / `scan_sessions` 语义不变。旧 JSONL 原字节不变，不生成旁路索引，不产生磁盘写入，也不要求手动迁移。
- 这一步减少启动时对全部 Journal 的重复读取/解析，**不减少磁盘占用，也不消除一次完整恢复所需的内存与 I/O**。

## 后续阶段的验收门禁

1. 为历史读取建立版本化的可丢弃索引或快照；以日志内容和 revision 校验，失配时退回原 JSONL 重放；恢复中断后不丢事件。
2. 仅对可证明不再写入的旧段做无损压缩。原日志保留到压缩产物完整校验、原子发布并通过重启/随机读取/追加回归；不得对运行中的会话原位压缩。
3. `request-audit` 对象的归档/清理必须从**全部**会话日志构建引用集；未知版本、损坏日志或无法读取的引用出现时停止清理，不能只凭文件年龄删除共享对象。
4. 新旧格式双读、迁移断点续跑、降级路径、跨平台文件锁与崩溃恢复都通过后，才能将磁盘回收作为默认行为。迁移前后用同一份真实历史测启动时间、峰值 RSS、磁盘实际块数与审计读取一致性。

当前第一阶段无须迁移；后续压缩/回收尚未实现，不应提前宣传磁盘空间已下降。
