# 第二阶段：闲置恢复快照与受限尾段重放（HISTORY-02b1）

## 目标与边界

降低**已经有有效快照的闲置长会话**首次打开时的完整 JSONL 解码、状态重建及峰值内存。
这不是模型 Compact，不删减历史，也不是把部分日志包装成可执行 `Session`。

本阶段实现两条加速路径：

1. 日志没有变化：读可校验的状态快照，不物化整份历史。
2. 快照之后只有模型选择、权限、Plan、Preset、用户改标题及其原子 RPC 回执：校验来源，增量折叠这些尾段事件。

**待执行输入、运行/中断工具、审批、问题及迟到答案、Goal 自动续跑、Schedule、Compaction、模型轮次仍走现有完整恢复链路。** 未支持的事件一律回退；不根据快照猜测它们已经完成。
活动任务快照加速属于后续 `HISTORY-02b2`，本阶段没有替换 Agent 的权威恢复机制。
首次没有快照、快照超界、历史索引不可用等情况仍可能完整读取。

## 职责分离

- `xharness-session`：可选 `Store::publish_recovery_checkpoint` / `recovery_tail`，及只读 `SessionRecoveryCheckpoint` / `SessionRecoveryTail`。其他 Store 默认不支持，保持完整重放。
- `xharness-session-jsonl`：`<id>.recovery-checkpoint` 的物理来源校验、版本、摘要、锁、限额及原子发布；不解释 Host 状态，不生成模型消息。
- `xharness-projection`：Metrics 私有折叠状态的序列化/恢复及继续折叠，复用同一 Typed/Web reducer；不另写一套 Token 统计。
- `xharness-host`：闲置资格判定、紧凑恢复状态、允许的元数据尾段及失败回退。Runtime 必须显式 `supports_idle_restore_checkpoint()` 才能采用，未知 Runtime 默认完整恢复。
- `xharness-agent` / Core / Provider：执行、上下文、Inbox CAS 与工具恢复不变；仍通过完整 `Store::load` 获取权威 Session。

## 快照保存什么

保存 Header、原始 `next_seq` / Revision，以及：

- 标题、模型及思考/上下文选择、权限、Preset、Plan、父会话/来源、暂停/委派状态、下一轮序号。
- 非活动 Goal 的现有展示状态；活动 Goal 不走加速。
- Token、每日用量、耗时、上下文压力的**私有折叠状态**，不是复制所有历史指标事件。
- 完整的 Admission 与 Session Mutation 去重回执，不以 ID-only 摘要损失重试返回内容。
- 已归属用户/模型或已耗尽标题生成重试的终态证据，防止标题后台检查马上重新物化整份历史。

不保存完整 Transcript、工具原始输出、Provider 请求快照、凭据配置、进程句柄、Channel 或活动任务。
Admission 中的原始用户输入仍是聊天数据的一部分；不把它当作可自动重执行的队列。
没有明确持久路由的旧会话，在恢复时使用**当前**配置默认值，不能把快照生成时的默认值固化成用户偏好。

## 资格判定与发布

只有完整日志已成功验证、Host 投影游标与日志一致、持久轮次关闭且没有待恢复工作，才发布闲置快照。
不能仅凭 UI `running=false` 认定安全；运行中的 Host 回调即使尚未退栈，也必须以持久轮次/Inbox/交互状态为依据。

禁止将以下状态认证为闲置：

- 任一 Inbox 待输入、未完成工具、未关闭普通轮次。
- 待审批、遗留待清理审批、待问题、未落 ToolResult 的问题。
- 已 Deferred 但答案未 Deliver 的问题（即使其 ToolResult 已完成）。
- 活动 Schedule、活动 Goal、Runtime 报告的后台/维护任务或检查失败。
- 未关闭的 Compaction。

在完整恢复及同步到持久边界时尽力发布；失败只损失加速，不使正常聊天/启动失败。
只保留一份当前旁路快照，原子替换，不为每轮保存一份快照。

## 来源校验与尾部边界

旁路 Envelope 包含版本、状态 Schema、Header、游标、Revision、源文件指纹、已验证前缀 SHA-256 和整个 Envelope Body 的 SHA-256。

- 发布必须匹配 Store 已验证的文件戳、序号和 Revision；不能把旧状态绑定到新文件。
- 日志必须完整换行终止，不能为破损尾部发布快照。
- 无变化时检查现有文件身份/长度/时间/固定大小采样指纹及快照摘要。
- 日志增长时，先确认同一文件并**流式计算旧前缀 SHA-256**，再读取尾段。旧前缀不反序列化、不常驻内存，但仍有 O(旧文件字节数) 的校验 I/O/CPU；不是只读几 KB 的承诺。
- 热缓存保存增量 SHA 状态；普通 append 只把新字节及必要换行纳入摘要，不在每次写快照时重新读整份文件。
- 尾段验证每个完整物理批次、连续 Revision / 原始 Seq / 事件 Revision，结束再检查源文件指纹。
- 压缩/替换、Header 失配、版本未知、缺失、摘要错、尾部破损、并发变化都回退完整恢复。
- Host 投影字段或 reducer 语义出现不兼容变化时，必须升级状态 Schema；旧快照按缓存未命中处理，不能以默认值掩盖不兼容的指标/去重状态。
- 元数据尾段额外复用原 `Session::restore` 的语义校验（仅独立元数据验证切片、重编号用于验证）。这个临时验证对象绝不交给模型、执行器、恢复器或作为历史返回。
- RPC 回执必须与状态变更同一原子 Revision，保留原始状态事件序号；已存在 RPC ID 冲突回退，不跳过副作用保护。

摘要是损坏检测，不是防同用户恶意修改的签名。既有会话进程锁、跨进程文件锁及原子文件替换继续提供协作写入一致性。

## 容量与内存

- 单个旁路快照编码上限 4 MiB。
- 尾段物理读取最多 8 MiB、4096 个事件；gzip 展开工作量受同一 8 MiB 预算约束，先检查声明长度再解压。
- 增长前缀摘要使用固定 64 KiB 缓冲区。
- 沿用存储读取并发上限 2，重型文件 I/O 在 `spawn_blocking` 中执行。
- 以上限制的是加速路径，不是聊天内容上限，也不是进程 RSS 的硬上限。超界后完整恢复，不截短数据或返回空历史。
- 不新增 `unsafe`、原始指针或 mmap；复用仓库现有的平台安全文件封装。

## 历史、标题与执行

快照恢复后的会话有正确权威游标，但不保留第二份模型 Transcript。
历史分页复用第一阶段偏移索引；实际执行、Fork、检索/导出等需要完整 Session 时仍读取原日志。
若历史索引失效/超界，也会回退完整历史路径，快照不承诺所有旧日志的全流程峰值都下降。

标题后台检查只在**来源仍有效、尾段受支持且标题终态明确**时跳过完整加载。未归属/待生成/来源变化仍使用原标题状态机，不抑制需要的标题生成。

## 验收门禁

远程测试比较快照与完整重放的完整 Host 摘要、指标、设置、游标及去重返回；逐个 Metrics 切点序列化再继续折叠也必须一致。
覆盖损坏/未知/超大旁路、旧格式及 v2 压缩、破损/非法 Revision/Seq 尾部、增长前缀变化、并发追加、发布失败、不支持的工作、中断工具不重执行、模型切换、配置默认值变化、标题后台不重新加载及错误不被隐藏。

Linux 隔离合成性能验收只是存储/Host 核心证据，不是已安装 macOS / Windows / WebKit 的实测。
跨平台 CI、真实最大旧日志验收、发布和本机替换另行执行。本阶段不会迁移、压缩或删除用户真实数据。
