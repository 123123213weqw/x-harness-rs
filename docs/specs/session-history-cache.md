# 前端闲置会话历史缓存

状态：2026-09-13，产品 Runtime 和打包补丁已实现；尚未发布或替换安装软件。

## 目的与边界

这是 Web/Tauri 共用的前端内存优化，不是模型上下文压缩。服务端对话、模型输入、工具结果原文均不删除或截断。

复用 `SessionManager`、`Session`、`ConversationNodeAssembler` 和现有 history 分页接口。保留 Session 与 scope，不执行 `dropScope`、不删除会话、不重置输入框。

## 策略

- 最多保留 **6 个闲置会话历史**。
- 闲置历史的**估算数据容量合计不超过 64 MiB**；数量或容量任一超标，按最久未访问顺序释放。
- 以上是可调整的内部策略常量，不增加用户配置项。
- 只有用户选择会话更新访问顺序，后台消息/状态到达不刷新 LRU。
- 当前会话、运行中会话、有待回答/审批、有排队消息、等待首轮启动、请求/命令/分页/缺口修复未完成的会话受保护。
- 受保护历史不纳入闲置上限，因此这**不是整个应用的硬内存上限**；不能为了内存取消用户任务。
- 单次微任务合并清理调度，运行期间不反复扫描大型历史估算大小；数据变化后，变成闲置候选时才重新估算。
- 缓存管理器不额外订阅 Session 数据通知，避免为了做缓存管理反而强制每个后台流式会话持续构建 UI 快照。

容量按字符串和对象结构估算，不调用 JSON.stringify 生成整份副本，无全局强引用 memo。该数值既不是精确 JS heap，也不是进程 RSS。

## 清理内容

清空 events、views、liveBuffer、Conversation 输入/上下文/位置索引和派生视图 builder，立即重建空的缓存 snapshot，状态改为 cold；增加 openGeneration。

保留：Session/scope 身份、输入和附件引用、问题/审批/队列、标题和管理器 projection store、原有的 UI scope 状态、原历史范围的起始 seq。

共享 projection store 同时支撑侧栏标题、Goal 等产品状态，**本次不清理它**。不能把“历史缓存已受限”说成“所有前端缓存均已受限”。独立插件缓存、图片缓存、编辑器和当前巨大会话仍需单独治理。

## 重新打开

1. 复用已有 `open()`，先请求最近 50 条消息。
2. 如果清理前加载过更早历史，使用 `beforeSeq` 逐页回补到原起始 seq，验证连续性、进展和请求 generation。
3. 一次安装恢复的窗口，继续使用现有 `chatScroll` 语义锚点/scrollTop 恢复。
4. 原范围不可用或请求失败，进入可重试 error 状态，保留恢复目标，不悄悄当成空白新会话。
5. 每个 await 检查 generation；旧 open/loadOlder 回包不能覆盖新窗口。
6. cold 会话的 `resync()` 保持 cold，重连不会自动把所有已淘汰历史重新拉回内存。

代价：命中缓存的会话切换行为不变；被淘汰会话需要网络加载。之前加载过很多历史页时，重新打开会有多次分页请求，以正确恢复旧位置为优先。后续可扩展按锚点区间加载，不能直接改成只读尾页造成无提示跳底。

保留的是原来已存储在 scope/插件中的 UI 状态；不新增所有工具卡片的跨卸载展开状态持久化承诺。

## 历史映射失败保护（2026-09-19）

`ui/overrides/atomic-history.js` 在完整历史替换和分页时创建临时组装器，完成事件关联、
reducer 和 view builder 后才发布。失败保留原始窗口、游标和已渲染消息；不跳过坏事件。
重连期间旧历史保持可见，失败显示既有错误提示及本地化“重试”按钮。
重试只读取历史，不重新提交 prompt、工具命令或审批回答。

缓冲的实时后缀按 seq 排序去重，缺口不强行拼接；失败保留缓冲等待历史恢复。
旧 generation 的异步响应仍不可覆盖新窗口。缺口恢复保留已加载的历史范围。
当前会话原始日志、模型上下文和工具结果不受修改。

暂存窗口与原窗口在提交前短暂并存，因此有额外的映射构建峰值；普通流式 append 不做整窗复制。
这不是原生 Rust Host 内存崩溃的修复，也没有声称所有实时 reducer 异常都已事务化。
Node 测试覆盖处理/视图构建异常；浏览器测试用实际压缩 classifier、ChatView 和重试按钮验证。

## 缓存测试与诊断

`scripts/test-session-history-cache.mjs` 在浏览器运行实际打包的 SessionManager、Session、Chat 定义和 assembler，而不是仅测试复制的假 LRU。

覆盖数量/容量、当前/运行/问题/审批/队列保护、LRU 顺序、分页范围恢复、失败重试、过期响应、cold 重连和 scope 删除。Chromium 检查 GC 后旧 raw history 弱引用失效；32 个合成会话做 JS heap 对照。

`SessionManager.historyCacheStats()` 仅返回数量、估算容量和淘汰计数，不含对话文本或凭据，不是新增服务端 RPC。

CI 同时运行 Chromium/WebKit；Mac/Windows/Linux 原生进程占用与长时间真实会话验收属于发布前后独立工作。
