# job_output 等待超时：单变量实验

## 边界

以 `dc4b53d`（PR #197 的 Shell 修复）为基线。仅替换 `job_output` 在 `wait=true` 时的 `timeout_ms` 解析：显式非法负整数应拒绝，不应静默采用默认等待。工具描述、Schema、30 秒默认、1–600000 ms 有效范围、输出、Job 生命周期与其它工具均不变。

## 验收流程

1. 同一契约测试先跑旧版，再跑候选；必须保留旧版失败及候选完整输出，不以模型报告代替测试。
2. 覆盖非法类型／范围、已完成 Job、合法边界／缺省、运行中等待超时、取消等待不取消 Job、游标增量与空重复页、完成唤醒、其它 Job、归属／错误游标与冲突参数。
3. 四 crate 回归与 Clippy 在 V100 执行；本机仅格式检查和 Python。同步两臂相同源码，预先确认只有一个生产文件不同；强制刷新源码时间戳避免之前发现的共享 target 旧产物风险，分别保存两臂二进制。
4. DeepSeek 与 V100 Qwen 27B 分别做普通后台验证编程任务和显式非法超时恢复任务，一组 A/B、一组 B/A；最多 8 次独立任务、30000 DeepSeek 未缓存输入 Token，不扩大样本追逐优势。
5. 工具 Definitions 每个请求完全相同；每臂工作区／JobRegistry／会话独立。代码产物必须通过固定测试、独立随机／边界检查和文件修改范围检查；后台测试必须从 job_output 收集到完成与测试输出。候选故障组必须用同一 Job id、合法参数恢复。
6. 原始请求、事件、usage、结果、产物、源码／二进制 hash 与分析保留；密钥仅经 stdin 传递，不写入证据。

## 结论口径

仅一个小编程 fixture，两个变体、每模型每变体一对；模型采样、服务器负载与共享 KV 缓存未固定。只评估参数正确性与模型恢复，不声称通用提速／更高缓存命中。刻意注入的参数错误与其它真实失败分开统计。
