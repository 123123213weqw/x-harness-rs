# 执行检查点与精确重复提醒

状态：2026-09-10，源码及远程回归已实现；发布/安装验收单独跟踪。

## 目标与边界

不注册新 Tool，不让模型输出私有续期 JSON，不增加判断模型。Core 在工具批次完成、下一次模型请求前统一检查：阶段是否接近结束、最近是否出现完全相同的工具观察。提醒只提供事实，是否继续通过正常的工具调用/最终回答表达。

这不是死循环证明器，不检测 A/B 交替、语义相似或“任务有没有进展”，也不自动取消重复工具。失败三次只是提醒，不是拒绝第四次执行。

## 配置和状态

`LoopConfig.checkpoints: CheckpointConfig`：

| 字段 | 默认 | 含义 |
| --- | ---: | --- |
| interval_steps | 1024 | 每个执行阶段的步数跨度 |
| notice_steps | 64 | 距阶段位置还有多少步时提醒 |
| repeat_error_threshold | 3 | 连续相同错误提醒阈值 |
| repeat_success_threshold | 5 | 连续相同成功结果提醒阈值 |

阶段不是硬限额。默认 `LoopConfig.max_steps = usize::MAX` 表示没有单独的步骤硬限额；显式设置的有限值继续作为硬限额，模型不能修改。现有总输出预算、网络恢复截止时间、工具超时、取消/审批约束不变，不能将“没有默认 128 步截停”理解成所有资源都无限。

状态保存阶段编号/阶段位置、待消费提醒、最近一个观察的 SHA-256/次数/已提醒标志。正常新用户轮次重新计步。已有的同轮审批/提问恢复会恢复该轮状态；普通崩溃仍遵循原来的中断收敛规则，不新增任意工具的自动重放。

## 主链路

1. 安全边界先处理用户控制与取消；达到显式硬限额则结束并保留 `limit_reached`。
2. 若距阶段位置不足提前量，或出现新重复提醒，合并成一条通知；同一待消费通知不再次生成。
3. ContextPolicy 先投影历史并校验固定 system prompt，然后追加临时 Harness 控制提醒，再进入 token guard、Provider 编码和请求审计。因此自定义 ContextPolicy/compact 不能无声丢掉提醒，提醒的 token 也计入预算。
4. 为兼容只支持首条 system 的 Provider，控制提醒使用带 `execution-notice-*` ID 的 user-role 消息承载。它不代表新增用户输入，不进入用户队列或 `derive_messages()` 历史。固定 system prompt 不被修改。
5. 仅在完整、合法的模型响应后消费提醒。正常工具调用表示继续，阶段向后移动 1024 步；最终回答正常结束。网络重试、半截工具参数、输出截断不能触发重复续行。
6. 工具仍由同一个 `xharness-tools` Executor 执行，不改审批、资源键、并发或副作用语义。

例：第 960 步后提醒；第 961 步模型正常调用工具，即进入阶段 2，新的阶段位置为 2048。无需在 1024 步额外请求一次模型。

## 重复观察

- 指纹：工具名 + 递归规范化的 JSON 参数 + 成功/失败 + 完整内容/错误，各字段长度分隔后做 SHA-256。
- 按模型原始调用顺序观察，不受并行工具完成时间影响。不同观察重置连续计数；每个连续段只提醒一次。
- 观察发生在模型侧工具结果截断之前；已知输出本身不完整时不做肯定重复判断。状态中不保存原始参数或输出。
- Registry 内部元数据 `repetition_exempt` 排除预期轮询；`job_output`、`job_list` 已标记。不会把这些元数据注入工具 Schema。
- 可选纯函数 `repetition_observation` 负责工具特有的稳定表示。bash/pwsh 保留退出码、信号、终止原因和 stdout/stderr，仅忽略 PID；后台启动或截断输出不比较。shell 返回外层成功但实际 exit 非零时，按内部 `success=false` 计入错误阈值。
- 通用结果默认精确比较；含动态时间或额外描述的不同结果可能不命中，这是保守的漏报，不使用模糊判断强行合并。
- 待发重复提示最多 16 条；与阶段提醒合并为一条请求消息，不增加模型调用。

## 持久化与 UI

- 新增 `run/checkpoint` durable event，状态快照随完整工具结果批次同一次 append 提交；发提醒先持久化，再发布实时事件。
- 无 notice 的内部快照映射为 hidden `xharness/internal`，不显示聊天卡片、不成为模型历史。
- 有 notice 时，实时路径和恢复路径共用 `web_execution_notice` 投影；前端复用 Conversation 注册与节点机制。
- 检查点/续行可展开查看；`turn/end: max-steps` 默认展开明确的停止原因，用户可发送“继续”开启新轮次。框架不自动重放已完成工具，但模型仍可能主动再次调用它们。
- 新 durable event 需要配套新二进制。**不要直接用旧版二进制读取已经写入新事件的数据目录**；降级需恢复升级前备份或提供显式迁移。

## 验收

自动测试：配置边界、默认超过 128 步、显式硬限额、成功/失败阈值、规范化参数、变化重置、不可靠输出、轮询豁免、单通知/单续行、请求重试与自定义 ContextPolicy、固定 system 不变、通知不累积、durable/live 一致、隐藏内部事件、真实 UI runtime 的 append/reload/prepend、Chromium/WebKit 展开及窄屏。

真实 DeepSeek Flash：临时工作区中的错误 Python 乘法函数，经读取、编辑、shell 验证后完成；阶段跨度缩为 2 以验证续行。该测试证明协议可用，不声称模型一定不会循环，也不是 1024 步实测。
