# AI 代审

## 范围与默认值

新增可选权限预设 `workspace-write-ai-review`。默认仍为原 `workspace-write` 人工审批，
Full access 保持原行为。新预设与 workspace-write 使用同一个系统沙箱、网络和文件权限；
不启用 Computer Use，不增加模型可见工具，不扩大 OS 权限。

GUI 会话权限菜单及默认会话权限设置均从 Host 目录读取该选项，选择持久化在原 Session /
Control 日志中。运行中的切换仍在下一真实 turn 生效。只有新模式的持久事件批次最后记录显式预设，
避免恢复时将 AI 代审错误降为普通 workspace-write；旧模式的事件顺序保持不变。

## 审批协议

沿用工具注册 `requires_approval`、Core 的审批桥和 Host 客户端响应接口。
已被 Guard 拒绝的调用不会进入审核。Host 在审批请求时调用当前路由的辅助模型，
使用模型目录最低支持思考档位，不继承主对话的思考强度。

每次审批发起一次独立 Provider 请求，不重放聊天历史，`tools=[]`，输出预算 512 token。
输入包括当前最近一条非 Compact UserMessage（若该条无文本，转人工而不是复用旧授权）、workspace、精确工具参数、调用 ID 和来源序号。
绑定 SHA-256 覆盖输入，作为审核请求可追溯标识。超过 64 KiB 的输入不截断授权或命令，
直接转人工。输出仅接受严格 `{"allow":true/false}`，未知字段、重复字段、工具调用、
非 Stop 终态、缺少终态、网络错误或累计正文/思考超过 24 KiB 都转人工，不重试。

审核完成后，复核会话/审批/调用 ID、路由、工作区、权限、turn 以及当前请求序号。
批准/拒绝通过内部 `ReviewToolDecision` 进入原 Loop。Core 在实际接收决定时再次比对
独立维护的真实用户请求事件序号与 SHA-256；不从 Compact 后的模型消息取授权范围。
请求身份由原始日志及成功追加回执更新，Compact 不改变身份，恢复审批时从原始日志重建。
相同文字的新用户消息也有新序号；已接收但尚未提交的 User/System Steering 也使审核结果失效。
因此 Host 检查之后紧接着发生的 Steering 不能让旧批准执行。

人工与 AI 决定共享单次决定认领，取消等待会释放认领，已接收的决定保持认领，重复/迟到响应不能重复批准。AI 拒绝记为独立审核拒绝，
不是用户拒绝；其模型推理不进入主 Agent 上下文，最终审批决定仍落在原历史中。

## 等待、异常与生命周期

- 全 Host 最多 4 个审核槽位，30 秒覆盖排队、准备、请求及决定提交。
- 超时、格式/网络错误、模型缺失或范围变化转人工，不默认批准，也不记为用户取消。
- 同一审批卡片用可选 `reviewing` 字段显示“正在代你审核”；此时允许按钮禁用，拒绝仍可用。
- 失败更新同一个相关 RPC 请求，恢复人工按钮；刷新基线保留当前阶段。
- 停止、取消、人工作答或审批关闭后取消审核请求；任务只弱引用 Host，不在上游等待时持有 Host。
- 重启后的旧审核结果不复用；原待审批操作可在新运行实例重新审核，结果仍须通过上述检查。
- 审核允许只批准本次操作；不会解除沙箱，也不跳过原文件版本、并发、超时和清理机制。

## 验收

1. 严格 JSON、完整终态、一次请求、零工具、最低思考档位。
2. 真实 Durable Agent → Core → ToolExecutor 链路的允许与拒绝，工具执行次数和日志一致。
3. 异常转人工后可正常批准；普通人工模式不调用审核模型。
4. 停止期间取消请求，迟到允许不能执行。
5. Core 处于待审批时注入 Steering，旧 AI 批准被拒，仍可人工结束审批。
6. 浏览器实际 React 卡片验证代审显示、禁止误点允许、拒绝可用、同请求回退人工。
7. 原权限切换、工具流水线、实时/历史投影、持久恢复及跨平台回归。

## 后续改进（不作为当前完成项）

- 独立选择审核模型、可配置预算与超时；当前复用会话模型辅助路由。
- 多轮含附件/子任务的授权摘要，以可信来源形成范围，不全量塞历史。
- 辅助审核 Usage 的独立成本展示和持久审计；当前原审批决定持久化，但不声称审核成本计入主轮 Token 圆环。
- 真实多模型误批准/误拒绝对照测试，持续调整审核策略。模型判断不是安全证明。

## Compact 审批回归修复

- 增加 Session 统一的真实用户请求查询，Host 与 Core 使用同一权威来源。
- Core 单独保存事件序号与原始请求文本哈希，通过成功的事件追加回执增量维护；摘要覆盖、工具输出和普通日志不会重置授权。
- 内部决定携带请求序号与哈希，在 Core 接收命令的串行边界复核；不移除待提交 Steering 保护。
- 回归覆盖实际自动 Compact 后批准/拒绝、错误或缺失序号、错误哈希、User/System Steering、相同文本的新请求、压缩后待审批恢复和空请求不复用旧授权。
- 语言字典门禁仅允许新增的代审文案，并对中英文精确断言；冻结基线及其他 ABI 检查保持不变。
