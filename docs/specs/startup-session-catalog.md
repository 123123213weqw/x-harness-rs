# 启动会话目录与按需恢复

## 问题与目标

当前 Native Host 在发布 `/health/ready` 前，对每个 `scan_startup_candidates()`
返回的会话调用 `Store::load()`。在本机约 324 个会话、5 GiB JSONL（最大单文件约
1.34 GiB）的情况下，桌面端 120 秒绝对启动超时会先于 `history_restore` 完成。

目标是让会话列表与旧日志回放解耦：启动时读取有界的持久元数据；同步恢复明确有
待执行工作、待审批、待回答问题或其他必须重接的会话；其余会话仅在打开或后台修复
时完整读取。不得删除、截断或静默隐藏任何历史日志。

## 权威性与故障规则

- JSONL 仍是权威来源。目录索引可丢弃、可重建，不可成为第二份可写对话历史。
- 每条索引绑定 JSONL 文件身份与内容指纹（至少长度、mtime、稳定文件身份及
  抽样哈希）；索引不匹配时，不得据其断言会话“无待执行工作”。
- 索引更新顺序为：先提交并同步 JSONL，再原子替换索引。索引写入失败不撤销已经
  成功的日志追加；下次启动将该条视作未知并安排修复。
- 对于旧版没有索引的会话，先凭不可变文件头公开最小列表项，并标记为“恢复中”。
  禁止对尚未恢复的同一会话执行新工具或接纳新轮次；后台校验完成后再开放操作。
  这使首次升级也能进入产品，而不把未知状态误判为安全空闲。
- 一个损坏的日志或索引只生成该会话的诊断，不得阻止其他会话及新会话使用。
- 后台恢复可取消，停止 Host 时必须等待或中止恢复任务，不能让其在关闭过程中
  新启动 Agent。所有恢复任务按 session ID 去重。

## 分层路径

1. **目录**：存储层扫描文件名和固定大小的文件头；读取有效的会话元数据索引。
   索引保留 `id/cwd/createdAt/updatedAt/title/parent/model/permission/blank`、日志
   指纹与明确的恢复需求标记。此阶段不构造 `Session` 或消息投影。
2. **必要恢复**：只完整加载索引确认有待处理输入、审批、提问、压缩、Goal／调度
   等工作或未安全结束的轮次。先接回持久交互，再发布 Ready；不得从“最近活动”
   推断是否需要恢复。
3. **Ready 与列表**：发布 Host Ready。列表能显示已索引的旧会话和无索引的最小
   项；无索引项显式标记恢复中，不伪造空历史或空队列。新会话不受旧日志扫描阻塞。
4. **旧会话按需恢复**：用户打开时优先加载该会话；其余在后台限并发重建索引。
   同一会话的按需请求与后台任务共用一次加载。历史分页沿用既有 `beforeSeq` API。
5. **大文件后续优化**：本阶段仍需完整回放被选中的 1.34 GiB 会话。轮次／事件
   偏移索引与真正的局部历史回放是独立后续工作，不应把它们冒充本次已完成。

## 回归门禁

- 旧格式、无索引、索引损坏、日志被追加后索引过期、日志尾部不完整、单文件损坏。
- 待执行用户输入、审批、提问、运行中工具结果未知、Goal／调度任务重启后各恢复
  一次；未恢复会话不能接纳新轮次，回答不会丢失或重复执行工具。
- 首次升级含大量旧日志时，Ready 不等待它们全部回放；列表不丢项，按需打开优先。
- 索引写失败、恢复任务 panic／取消、Host 关闭与恢复竞态均能生成诊断并安全重试。
- RWKV Ubuntu 上执行单元、重启、损坏日志和进程启动回归；V100 恢复联通后，再以
  大量小会话和至少一个巨型会话做冷／暖启动计时、峰值 RSS 与真实模型多轮回归。
  Mac 本机不执行 Rust 编译。

## 当前代码落点

- `crates/xharness-session/src/store.rs`：目录及索引协议。
- `crates/xharness-session-jsonl/src/lib.rs`：索引原子持久化、指纹和迁移读取。
- `crates/xharness-host/src/restore.rs`：必要恢复、延迟会话状态及按需恢复。
- `crates/xharness-host/src/rpc/session.rs`：列表与历史请求的恢复状态。
- `crates/xharness-host-app/src/main.rs`：Ready 门禁与后台恢复生命周期。
- `apps/desktop/src-tauri/src/sidecar.rs`：保持超时兜底，不用扩大超时掩盖全量回放。

## 当前实现及边界

- Native 进程先建立索引／文件头的最小会话目录，再同步回放有效索引明确标记
  `needs_recovery` 的会话，然后发布 Ready。旧版无索引或指纹过期的日志在目录中可见，
  按需打开或 Ready 后顺序后台校验；未恢复前，同会话的 RPC 会先等待校验，禁止
  使用空投影接纳新工具或轮次。
- 索引仅在一次完整回放后发布，写入后若日志又追加，文件指纹使索引失效。因此本阶段
  已解决启动被历史回放阻塞的问题，但尚未实现每次事件追加时的**增量索引维护**；
  频繁修改的会话下次启动会再次进入后台校验，而不是误认为安全空闲。
- 第一次升级时，历史日志均没有索引。Host Ready 不等待它们，但其待审批／待回答／
  运行中任务需要后台读到该条之后才能接回；这与“已建立索引的必要状态同步恢复”
  不同，不能声称旧历史的待执行工作在 Ready 前已全部恢复。
- 后台任务的异步阶段可取消且不在关闭后启动新 Agent；已经交给文件存储
  `spawn_blocking` 的单次日志读取无法中途强制停止。下一阶段需给巨型日志解析加入
  取消检查或限时分页重放，以保证极端文件上的退出时间。
