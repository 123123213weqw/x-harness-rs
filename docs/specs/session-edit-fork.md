# 历史消息「编辑并 Fork」

## 行为

- 已完成轮次中的用户消息提供「编辑并 Fork 到新对话」，与原有「编辑并重新发送」并列。
- 先读取原消息的文字和附件字节；附件缺失、类型不受支持时不创建子会话。
- 子会话只复制该消息**之前已完成**的轮次。首条用户消息也可作为边界，得到空历史子会话。源会话历史、运行状态和草稿均不改动。
- 原文字及附件写入子会话草稿，不自动发送。用户可以继续修改、取消；刷新后沿用已有编辑草稿的 IndexedDB 恢复机制。
- 子会话头部的来源面包屑可返回父会话。来源作为 `session/fork-origin` 持久事件保存，重启后仍可恢复；不是子 Agent，也不进入模型上下文。

## 协议与边界

- `session.fork` 新增可选 `beforeUserSeq`，与 `atSeq` 互斥。它必须指向真正的 `user/message`，后端以该消息之前最近的 `turn/end` 作为复制终点；没有已完成轮次时只保留轮次前的控制事件。
- 精确切割要求权威 Session 日志；仅有旧式内存消息缓存时显式返回 `fork-unavailable`，不能生成历史与模型上下文不一致的子会话。
- 常规 `atSeq` Fork 保持原接口行为，额外记录来源元数据。错误边界不会悄悄退化为完整会话复制。
- 因目标消息不在子会话历史内，不能在子会话使用旧 `image_ref`；前端先从源会话读取附件，生成新草稿 `File`，发送时作为新附件入库。
- 不实现同会话回退、工作区文件回退、自动发送或文件系统分支。

## 回归

- 后端：首条与后续用户消息切割、无效消息序号、来源重启恢复、旧 `atSeq` Fork、历史投影一致。
- 前端：草稿恢复、附件字节复制而非旧引用、非法内容拒绝、编辑生命周期、浏览器 UI。
- Rust 编译与测试依照仓库规则只在 `WZU_Server` 远程运行。
