# 工具参数生成进度

## 目的

把“模型还在写工具参数”和“工具已开始执行”明确分开，避免用户把参数生成耗时误认为 Bash 加载、审批或执行耗时。此功能仅改前端，不提前执行未完成的调用。

## 数据与边界

- 复用统一的 `assistant/chunk → tool-call-delta`：按调用 ID／块索引聚合 `argumentsDelta`；不依赖某个模型品牌。
- 前端块增加可选 `startedAt`，取该块首个规范化工具增量的事件时间，后续增量保留；不是新增 Host DTO，也不进入最终模型参数。
- 卡片显示工具名、收到的 UTF-8 字节数和首片段至当前的秒数。字节不是 Token；未知最终长度，因此不显示百分比。
- 时间使用客户端当前时间减事件时间，包含片段间等待，依赖两端时钟；不是 TTFT、服务端模型计算耗时或工具执行耗时。
- Provider 返回增量时即可展示；若接口缓冲到完整调用才返回，不伪造逐字生成，也不能靠 UI 提前拿到参数。

## 展示与交互

1. 默认折叠，显示“正在生成工具参数”，可点击或键盘 Enter 展开。
2. 展开后说明工具尚未执行；支持“内容预览／原始 JSON”切换。
3. 内容预览只解码顶层常见文本字段（command、content、patch、new_string 等），不把嵌套键或字符串中的伪键当作代码。
4. 不完整 JSON 允许展示，未完成的转义等待后续片段；不验证或执行该片段。React 纯文本渲染，不解释 HTML。
5. 单个预览最多 16,384 个 UTF-16 码元，边界不留下半个代理对；只限制展示，原始 `argsRaw` 不截断，最终调用不改写。
6. 闭合卡片不解码长参数；正文最大高度 260px，窄屏 200px，可滚动，不主动跳到末尾打断阅读。
7. 复用 transcript 状态桥，参数追加及窗口化卸载／恢复保留展开与显示模式；重试首片段时间变化后使用独立展示状态。
8. 复用既有 `preparingCall`／可见性生命周期。完整的小 JSON 不再显示生成卡片；正式工具事件交给现有 ToolRow。大输入等待最终交接，不因看似完整就提前执行。
9. 取消、终态和卸载清理秒表定时器；并行调用各自独立，不把多个工具混成一个状态。
10. 中英文词条、键盘焦点、`aria-expanded`／`aria-controls`、减少动画偏好及窄屏布局均支持。字节变化不逐片段触发屏幕阅读器播报。
11. 配色严格复用现有 Theme 的 `--dsw-*` 变量：主／次文本、边框、浮层、代码底色与灰色状态点；删除单独蓝色及蓝色兜底。预览也直接加载维护的主题样式与 `monochrome.css`，不另建浅／深色调色板。错误、成功等语义状态颜色不做全局去色。
12. 旧主题中的 Preparing 行内徽章样式排除新的生成卡片，避免 `inline-flex` 和整块闪烁覆盖纵向布局。只允许状态点轻微动画，阅读内容不跟着闪烁。

## 验证与预览

- `node --test scripts/test-tool-argument-progress.mjs`：真实出厂工厂的纯展示函数、Unicode／转义、限制、字节与投影首片段时间。
- `UI_TEST_DEPS=... UI_TEST_BROWSER=chromium|webkit node scripts/test-tool-argument-progress-browser.mjs`：真实平台、AssistantMarkdown 与 ToolRow 的浏览器回归。
- `node scripts/preview-tool-argument-progress.mjs`：仅监听 `127.0.0.1:4186`，展示实际 TS 组件，使用合成数据；阻止 Host 引导，不连模型、不执行脚本、不读写会话。
- 保留原工具可见性、历史分页、重试、取消和工具行回归，不修改原断言来适配新 UI。
- 此预览不等于安装版已升级；完整桌面原生验收和正式发布属于后续门禁。
