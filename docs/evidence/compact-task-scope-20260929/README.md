# Compact 历史任务偏移：真实 DeepSeek 探索性 A/B

日期：2026-09-29。模型：本机已配置的 `deepseek-flash` 官方端点。摘要使用独立 `low` 推理档，后续 Agent 使用 `max`；`temperature=0`，但服务端仍可能产生非确定性输出。脚本为 [`scripts/eval-compact-task-scope.py`](../../../scripts/eval-compact-task-scope.py)。

## 方法

- 依据用户真实遇到的“只问机器负载，却回到旧实验”的结构，**合成**一段旧文档质量实验会话；未向服务端发送原始聊天记录、账号资料或密钥。
- 用旧版和新版摘要指令分别让真实模型生成 Checkpoint；随后在相同 System、`bash` 工具定义、合成工具结果和新用户问题下多轮调用模型。
- 工具调用只被记录并返回固定合成结果，**没有执行模型生成的命令**。因此这是指令遵循/工具选择试验，不是实际机器性能测试，也不等价于完整的 18 工具生产 Host。
- 三个问题：模糊的“现在机器负载呢”、明确的“先别继续旧实验，只看 CPU/内存/GPU”、明确的“继续旧实验，先核对结果完整性”。每组每臂 3 次；旧/新执行顺序交替。
- 判定“越界读取旧项目”仅统计进入 `experiments/quality_eval/`、`metrics.csv` 或 `manifest.json` 的命令；为了归因资源占用而查看进程名不计入。另做无 Checkpoint 新会话基线和无工具的“明确继续”意图识别。

## 观察

| 场景 | 旧模板 | 新模板 | 解释 |
|---|---:|---:|---|
| 模糊负载问题，进入旧实验结果文件的回合（两批，共 6 次/臂） | 3/6 | 1/6 | 新模板有正向信号，但样本量小，不能当作显著性结论 |
| 明确说“别继续实验”，进入旧结果文件的回合 | 0/6 | 0/6 | 明确的最新用户范围比摘要措辞更可靠 |
| 新会话无 Checkpoint，进入旧结果文件 | — | 0/3 | 旧历史是偏移来源之一；基线本身也不能覆盖生产长上下文 |
| 明确说“继续旧实验”，能识别“先核对结果完整性” | 3/3 | 3/3 | 新模板没有把用户明确的继续请求抑制掉 |

新摘要不再包含 `## Next Step`，也不再把所选旧片段内的用户请求断言为“当前 active task”。但**两臂在模糊负载问题的最终回答中仍经常主动提到旧实验**，有时还建议接着做。也就是说，修改 Compact 能降低一部分旧文件探索，却不能独自解决“回答范围”偏移；后续应独立验证主 Loop 对最新用户请求的范围/结束条件，而不是继续针对本样本堆叠 Compact 特例。

“明确继续”的多轮合成 Shell 试验没有完整结束：固定工具结果无法真实模拟任意文件命令，模型因此反复探查。该部分只保留工具选择轨迹，**不用于判断旧/新哪组完成任务更好**。

## 证据与限制

- `report.json`：首轮候选模板的探索性试验；`report-v2.json`：修正“active task”表述后的最终候选、无 Checkpoint 基线及继续意图识别。
- JSON 只保存合成历史、模型生成的摘要、命令、最终正文、Token 用量与延迟；不保存密钥或私有 reasoning。
- 两批各自重新生成摘要，不是配对固定摘要；每组仅 3 次。工具只有一个模拟 `bash`，没有真实 270 条消息、18 个工具、网络中断或运行中任务。不能据此宣布生产偏移已修复。
